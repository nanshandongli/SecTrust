# 诚实边界范式（Honest-Boundary Paradigm）

> **一句话**：所有对外材料（产品分析、证据页、触达话术、白皮书、导出件）统一采用
> 「**先讲天花板，再讲数据**」的写法——先把能力边界和不可外推的缺口说在前面，
> 再给实跑数据兜底。这是本项目建立信任的**标准范式**，不是可选风格。

本文把 `PRODUCT_ANALYSIS.md` 第七节（尤其 §7.3）里被验证有效的诚实边界写法
固化为可复制的规范，供所有对外材料引用。

---

## 1. 为什么它是信任建立方式（而不是示弱）

- **先讲天花板 = 主动定义坐标系**。读者还没质疑，你已经把"能说到哪、不能说到哪"
  框好了。对方不会再拿"你这数字能代表生产吗"来将你军——因为你先说了不能。
- **再讲数据 = 给已声明边界内的硬证据**。天花板之下的数据是"兑现承诺"，不是"夸大"。
  可信度来自"边界内可复跑、可审计"，而不是"数字越大越好"。
- **顺序不可反**。先抛漂亮数字、再补"但是仅限单机"，会被读成"先吹后找补"，信任归零。
- **它筛选种子用户**。愿意为"诚实 + 可审计"付费的人，正是专业版要找的人；
  想听"最强最全"的人，本就不是目标客群（见 §5 克制边界）。

> 语出实践：`PRODUCT_ANALYSIS.md` §7.3 与 `docs/seed_user_outreach.md` 采用此写法后，
> 触达话术明确"先讲天花板"，并把"吞吐/延迟不往外推"放在付费点之前——这是被确立为
> 标准范式的原点。

---

## 2. 范式结构（三段式标准骨架）

任何对外材料，建议按以下顺序组织「证据 / 能力」章节：

```
① 天花板（Ceiling）   —— 先说清环境边界与不可外推的缺口（1~3 句，置顶）
② 数据（Evidence）    —— 边界内真实跑出来的、可复跑可审计的证据
③ 诚实声明（Caveat）  —— 数据口径说明：量级估算≠账单、审计证据≠漏洞判定等
④ 下一步（Next step） —— 缺口正好是付费点 / 路线图起点，把"短板"转成"价值"
```

**顺序铁律**：① 必须在 ② 之前。③ 必须紧贴 ②。④ 由 ① 的缺口自然引出，不另起夸大叙事。

## 3. 可直接套用的模板

### 3.1 证据 / 数据章节模板

> **环境边界（先讲天花板）**：本次验证为「______」（如单宿主 + 同机多进程；协议兼容
> `FakeRedisServer` 协调后端，非官方 Redis）。真实跨机房还会叠加延迟 / 分区 / NFS 失效等风险。
>
> **实跑数据（边界内可复跑）**：
> | 不变量 / 指标 | 本次 | 说明 |
> |---|---|---|
> | ______ | ______ | ______ |
>
> **诚实声明**：上述吞吐/延迟数字**不应直接外推**到分散物理机；成本估算为公开挂牌价
> 静态快照的量级值，**非账单**；审批/扫描记录是审计证据，**非漏洞判定**。
>
> **下一步**：把本地不变量放大到生产尺度、可外推，正是专业版付费点之一（见 §8）。

### 3.2 导出件 / 白皮书模板

在每份对外产物末尾固定一段「诚实边界声明」，例如（已用于审批链 PDF 导出）：

> · 本报告仅记录审批决策与轨迹证据，不构成漏洞或风险判定。
> · 风险等级依据动作是否属于高危集自动标注，属策略口径而非扫描结论。
> · 时间戳来自本机时钟，跨时区展示未经换算。

## 4. 发布前自检清单（Checklist）

在对外发布任何材料前，逐条确认：

- [ ] **天花板在前**：环境边界 / 不可外推缺口是否在数据之前、且足够具体（不许只写"仅供参考"）？
- [ ] **数据可复跑**：引用的数字是否来自真实实跑、且生成脚本零依赖可复跑（如 `tools/gen_evidence_report.py`）？
- [ ] **口径诚实**：成本/估算是否明确标注"非账单"；审计记录是否明确标注"非漏洞判定"？
- [ ] **不夸大外推**：是否出现把单机数字直接说成"生产基准"的表述？如有，删。
- [ ] **缺口=价值**：短板是否自然转成付费点 / 路线图，而非另起一个夸大故事？
- [ ] **零真实泄露**：若含扫描/密钥内容，是否 0 真实泄露凭证、假密钥已 `scanner:allow` 豁免？

## 6. 反例（禁止写法）

- ❌ "我们支持 1000+ 任务/秒的分布式吞吐"（先抛数字、无边界）。
- ❌ "成本约 $X/千次调用"（把量级估算当精确账单）。
- ❌ "审批链导出即合规认证"（把审计证据当合规背书）。
- ✅ 反过来：先讲"单宿主本机多进程、数字不往外推"，再给本机实测，再标"真机基准=付费点"。
