## 一、一句话说明白

**给一群 AI 办一家"公司"。**

公司里有任务看板（谁干什么、干到哪步）、有老板审批（高风险先批后干）、
有隔离工位（在笼子里干活）、有质检员（不合格打回）、有记事本（跨会话记得事），
还有一条流水线——你说一句话，它自动拆成工序，派给多个 AI 并行加串行地干完。

这家公司只有一个"文件柜"（SQLite 数据库），不依赖任何第三方包，
`python mcp_server.py` 就能开张。

---

## 二、它解决三个痛点

1. **单个 AI 只是聊天对象，不是同事。** 你让它写方案，它写完就完了——不会分工、不会协作、不会互相检查。
2. **让 AI 干活不放心。** 它说"完成了"就真完成吗？它跑的命令会不会碰密钥？产出能直接外发吗？
3. **多个 AI 各干各的。** 没有共同工作台：A 的产出 B 看不到，进度靠你人肉同步。

SecTrust 把这三件事做成基础设施：**共享一张任务表、每个关键动作留痕、人类在关键节点拍板。**

## 三、九个部件，各用大白话讲一遍

### 1. 任务看板 —— "公司的工单白板"

所有任务落在一张共享表里：登记、认领、心跳、完成、失败，全程留痕。
多个 AI（不同进程、甚至不同机器）同时抢一个任务时用"原子认领"——
数据库保证只有一个抢得到，不会两个 AI 做同一件事还互相覆盖。
浏览器打开看板网页，实时看每个任务的状态、依赖关系和阻塞传播。

### 2. AI 同事团队 —— "不同特长的员工，随你换"

- **模型可换**：OpenAI 兼容 / 本地 Ollama / 演示用 Mock。没配密钥也不假装——
  明示"这是假数据"，链路照常跑通。
- **渠道可换**：企业微信 / 飞书 / 演示渠道。
- **技能可挂**：本地技能目录、GitHub 技能源。远程代码等于信任边界，
  文档明确要求锁定 commit/tag，不静默拉最新。

### 3. 老板审批 —— "报销式管理，默认不批"

高风险动作（外发产物、执行扫描、自动裁决）一律先挂起，等真人点批准。
**超时等于拒绝，绝不默认放行。** 这是全套系统最重要的安全承诺，
而且它是默认值，不是可选项。

### 4. 隔离工位 —— "给每个 AI 一个笼子加一张桌子"

每个 AI 同事有独立工作区：干活目录（命令在这儿跑，沙箱管着）、
待发送箱（产物放这里，审批后才允许外发）、状态文件（跨重启还记得自己干到哪）。
诚实说明：本机版沙箱是弱隔离（防误伤，不防同机逃逸），
要强隔离请接 Docker / E2B——文档里明示，不含糊。

### 5. 手脚 —— "能真的上网，能真的说话"

- **浏览器**：驱动真实 Edge，能开网页、点按钮、填表单、等元素出现、截图
  （真机全流程验证过，用完进程树杀干净）。
- **语音**：文字转语音，可发到消息渠道；合成失败会明说失败，不假装已发送。

### 6. 记事本 —— "跨会话的记忆"

偏好、事实、经验存本地数据库；检索走三路融合（语义相似 + 关键词 + 实体）。
接进来的外部 AI 也能读写同一份记忆——"你告诉过它的事，换个 AI 也在。"

### 7. 安全审查 —— "入职背调加代码审查"

78 条检测器扫仓库里的密钥泄露（覆盖 50 家厂商，含阿里云 / 腾讯云 / 企微 / 飞书 / 微信支付），
香农熵兜底防"像密钥的随机串"，结果可输出 SARIF（GitHub 等平台直接认）。
扫描请求自己也要过审批，不绕过安全模型。

### 8. 流水线大脑 —— "你说一句，它排工序"（核心能力）

- **拆解**：一句需求自动拆成任务图（调研 → 文案 → 设计 → 合规 → 汇总）。
  信息抽不到就标 `<待补>`，不编造。
- **排队**：谁先谁后由依赖决定；能并行的自动并行（按波次发）；
  一步失败，下游自动阻塞，不会拿着坏输入往下跑。
- **省钱**：简单需求（如"写个周报"）不拆，一个任务直出；复杂需求才上全流水线。
  判据可解释，可人工强制覆盖——**不为简单事付全价协同成本**。

### 9. 三种协作方式 —— "不止流水线一种"

| 方式 | 大白话 | 例子 | 状态 |
|------|--------|------|------|
| 流水线 | 大项目拆工序，上游喂下游 | 双十一营销全案 | ✅ 已跑通 |
| 迭代打磨 | 一个干、一个审，不合格打回 | 代码 / 文案多轮润色 | ✅ 已跑通 |
| 投票择优 | 同一件事几个 AI 各出方案，按同一套标准打分 | 高风险决策参考 | ✅ 已跑通 |

投票有条重要纪律：**打分只出推荐，不自动生效**；几个方案打平、没有评判标准、
或者没交齐，一律转人工——不硬裁。

## 四、拿什么证明不是 PPT 功能

| 证据 | 说明 |
|------|------|
| 两个 AI 下完一整盘象棋 | 两个独立进程只靠共享数据库 + 事件总线，跑完 65 手直到将杀——证明协作底座是真的 |
| 报告流水线端到端 | 拆解 → 产出带占位符被打回 → 修订通过 → 数据冲突待人工 → 人工裁定 → 素材两版入库 → 全部完成 |
| 真浏览器全流程 | 真 Edge 上点击 / 输入 / 等待 / 截图全通过，无残留进程 |
| 612 项自动化测试 | 含并发抢单、故障注入、跨实例一致性；在"一有资源泄漏就报错"的严格模式下全过 |
| 压测曲线 | 同机 8 进程写 684 TPS；认领测试 50/50 抢到、0 重复 |

## 五、诚实的边界（用前必读）

1. **是原型，不是商品**：未上架、无真实用户、无真实流量；数字可复现，但场景是演示级。
2. **本机优先**：跨机器协作要接 Redis，且**跨机压测未做**（当前曲线仅同机）。
3. **拆解器认模板**：规则版只认内置模板结构；LLM 版已有，但没经过真实大规模需求检验。
4. **真机联调缺凭据**：企业微信 / 飞书 / OAuth 的代码齐了，差真实账号密钥（需使用者参与）。
5. **沙箱分档**：本机版弱隔离（文档明示），生产请接 Docker / E2B。
6. **判据的质量决定择优的质量**：质量规则本身写得松，投票挑出来的"最优"也松。

## 六、适合谁

- **个人开发者 / 小团队**：想要一个本地跑、全程留痕、关键步骤不放权的多 AI 协作台。
- **数据不出内网的场景**：数据是一个文件，易备份易迁移。
- **教学 / 参考**：零依赖看懂"多 AI 协同"的最小可行实现长什么样。

**不适合**：需要水平扩展、高并发写入、多租户 SaaS 的场景。
